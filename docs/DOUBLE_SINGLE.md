# Две FP32 в дифракционном ядре

На RTX 3080 Ti можно явно выбрать профиль `double_single`:

```bash
make -C gpu fp32_ds GPU_ARCH=86 GPU_LTO=1 -j4
gpu/bin/mbs_po_gpu_float_ds --version
gpu/bin/mbs_po_gpu_float_ds --method po --backend cuda \
  --particle 1 100 50 --ri 1.3116 0 --wavelength-um 0.532 \
  --fullauto 0.02 --fullauto-theta-range 170 180 --output result --close
```

Для RTX 5080 задайте `GPU_ARCH=120`, используйте CUDA >=12.8 и
поддерживаемый ею GCC. Установщик RTX 50 также принимает
`--with-double-single`; он сохраняет обычные FP32 и FP64 сборки.
На V100 предпочтительна прежняя сборка: этот профиль там был медленнее.
Ни одна прежняя цель сборки не меняет арифметику неявно.

Профиль хранит чувствительные промежуточные значения в виде суммы двух
FP32: старшей и младшей частей. Он использует явное округление и FMA для
фаз, моментов многоугольника, устойчивого предела краевого интеграла и
суммирования ориентаций. Геометрия трассировки, коэффициенты Френеля,
оптический путь при масштабировании и поглощение сохраняют FP64.
Матрицы на GPU и передача данных остаются FP32. Это не полная замена
IEEE FP64: диапазон показателя степени остаётся как у FP32.

Для фазы до 2^20 радиан применяется сокращение аргумента с двумя частями
π/2 и полином. Вблизи вычитания близких фаз используется более точный
полином. За пределами этого диапазона синус и косинус вычисляются в FP64
от уже полученного аргумента; это не восстанавливает округление предыдущих
операций. Для существенно более крупных размерных параметров следует
проверять результат относительно FP64. `GPU_FAST_MATH=1` запрещён для DS.

На RTX 3080 Ti в фиксированной проверке столбиков 794,3 и 1000 мкм
получено ускорение всего запуска 1,91–1,92× в когерентном и 1,26–1,30×
в некогерентном режиме относительно `float_reduced`. Это не прогноз
ускорения всей адаптивной кампании: трассировка, подбор и сохранение
результатов имеют отдельную стоимость.

Проверка 575 углов и восьми наборов по 4096 ориентаций дала максимум
|ΔMij|/M11 относительно FP64 0,01882% и 0,02744%. Среди элементов
|Mij|≥0,01M11 максимум собственной относительной ошибки составил
0,7293% и 0,4090%. Отличие DS от прежней смешанной арифметики было
не более 0,0000268% M11. Эти результаты описывают арифметику на одинаковых
выборках, а не достигнутую точность ориентационного усреднения.

Проверки арифметики:

```bash
g++ -O3 -std=gnu++11 -Isrc/cuda tests/test_double_single.cpp -o /tmp/test_ds
/tmp/test_ds
nvcc -O3 -std=c++11 -arch=sm_86 -Isrc/cuda tests/test_double_single_cuda.cu -o /tmp/test_ds_cuda
/tmp/test_ds_cuda
python3 tests/test_gpu_reduced_profiles.py --candidate gpu/bin/mbs_po_gpu_float_ds
```

При восстановлении `fullauto` обычная проверка требует тот же бинарник.
Переход `float_reduced → float_ds` допускается только с отдельным
сертификатом `FULLAUTO_NATIVE_COMPATIBILITY_DS_NONABS_V2`, который связывает
хеши старого и нового бинарников с хешем файла численной проверки.
Этот переход ограничен непоглощающими частицами (Im(m)=0): старые
версии имеют отличия в обработке поглощения. Для поглощения нужна новая
задача или отдельная проверка совместимости.
Дополнительно должны совпадать архитектура, компилятор, точность хранения,
OpenMP/MPI и остальные параметры профиля. Обычный сертификат V1 не
разрешает менять арифметику. Не создавайте сертификат по одному совпадению
строк версии: нужны численные проверки конкретных бинарников и режимов.
