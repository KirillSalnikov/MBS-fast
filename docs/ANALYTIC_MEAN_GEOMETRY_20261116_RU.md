# Повторное использование геометрии аналитических средних

`AnalyticFacetAverage::PrepareMeans` теперь строит правило Гаусса один раз на уровень уточнения, а расстояния между узлами на рёбрах — один раз на представитель грани. Все углы используют эти расстояния. Радиальная функция остаётся зависимой от угла и показателя преломления. Порядок суммирования внутри интеграла сохранён; вызов функции интегранда может инлайниться.

Кэш расстояний общий для одного прохода и ограничен 64 МиБ данных и таблиц векторов; накладные расходы аллокатора в этот предел не входят. Для пар рёбер, не поместившихся в кэш, используется исходный расчёт расстояний. Кэш освобождается после прохода; это не новый файловый кэш и не чекпоинт. Требуется учитывать до 64 МиБ дополнительной RAM на одновременно подготавливаемую аналитическую модель.

## Проверка

Таблица ниже заменяет первоначальный замер: первый механизм паузы пропускал процессы, принятые новым диспетчером и уже не являющиеся его дочерними. Повтор выполнен с проверкой состояния всех контроллеров кампании и их работников. Численные проверки первого прогона сохранили силу; его время не использовано как изолированное измерение.

На gpu2 (RTX 3080 Ti, FP32 с double-single фазой) проведены ABA-запуски на 65 углах 0–180°, 32 одинаковых ориентациях, phi=8, n=6, balanced cutoff и analytic facet average. На время проверки производственные процессы приостановлены с независимым таймером возобновления и затем возобновлены без перезапуска.

| Форма и режим | Исходный / новый / исходный, с |
|---|---|
| Произвольная, когерентный | 6.777 / 2.922 / 6.578 |
| Произвольная, некогерентный | 6.728 / 2.921 / 6.576 |
| Буллит, когерентный | 3.622 / 2.571 / 3.622 |
| Буллит, некогерентный | 3.572 / 2.571 / 3.623 |
| Дроксталл, когерентный | 0.567 / 0.316 / 0.516 |
| Дроксталл, некогерентный | 0.517 / 0.317 / 0.519 |

Произвольная частица: Dmax=15.85, lambda=.355, m=1.3243, circular shadow. Буллит: параметры геометрии 10 и 9.85, lambda=.4, m=1.3194, facets shadow. Дроксталл: параметр радиуса 5, lambda=1.55, m=1.2906+0.00042407i, circular shadow. Размерности — мкм.

Все 16 элементов и отношения к M11 проверены с заранее установленным пределом 3e-5. Максимальное фактическое отличие Mij, нормированное на исходный M11: 5.29e-8; отличие отношений: 4.93e-8. Повторы исходного GPU-бинарника также не побитово идентичны. Численные результаты и хэши бинарников: `tests/analytic_mean_geometry_20261116.json`.

Дополнительные CPU-пробы на 65 и 257 углах дали ускорение подготовки средних 2.46 и 2.92 раза; проверены поглощение, facets shadow и принудительно нулевой кэш. Максимальное абсолютное отличие средних в расширенных пробах 5.69e-14.

Это фиксированные задачи, не доказательство ускорения всего адаптивного fullauto или постоянной загрузки GPU >=50%. На коротких задачах время инициализации CUDA заметно; длинные производственные задачи требуют отдельного наблюдения.

## Воспроизведение

```
python3 tests/test_analytic_mean_geometry.py \
  --reference /path/to/old/mbs_po_gpu_float_ds \
  --candidate /path/to/new/mbs_po_gpu_float_ds \
  --particle-file /path/to/arb1_planar_mbs.dat \
  --output /path/to/new-validation-directory
```

Для сравнения времени выделите свободную карту и CPU. Скрипт сам не останавливает другие процессы; он сохраняет команды, матрицы, логи и результат проверки. Формат файла произвольной частицы — MBS, в приведённых замерах использована форма arb из текущей серии.

## Полный fullauto, контрольный ABA-прогон

На той же RTX 3080 Ti выделены четыре физических ядра. Прочие контроллеры кампании, включая принятые новым диспетчером, и их работники проверенно приостановлены, после теста возобновлены без перезапуска. Реальная задача: arb Dmax=15.85 мкм, lambda=1.55 мкм, m=1.2906+0.00042407i, 0–180°, допуск 4%, coherent PO, staged cutoff, проверки симметрии и дополнительные финальные проверки отключены, чекпоинты отключены.

Время исходный / новый / исходный: **227.103 / 214.141 / 227.104 с**. Ускорение всего адаптивного расчёта **1.061×**, сокращение времени **5.71%**. Все три прогона завершились на раунде 5 с n=8, phi=8, 150 рассчитанными углами и оценкой ошибки около 3.286%. Итоговая сетка из 892 выходных строк совпала; она содержит интерполированные углы. Максимальное отличие всех16 элементов между первым и новым прогоном: 6.34e-8 M11, отношений: 7.42e-8.

Средняя загрузка GPU в одиночном полном расчёте: исходный29.2%, новый28.3%; доля секундных отсчётов ниже50%:71.8% и75.2%. Поэтому ускорение этого компонента **не решает задачу постоянной загрузки >=50%**. На основном усреднении остаются короткие запросы по нескольким углам и повторная CPU-подготовка пучков. Уменьшение времени важнее повышения загрузки за счёт лишней работы.

Машинный отчёт: `tests/analytic_mean_fullauto_20261116.json`. Это один представительный полный расчёт; фиксированные тесты выше не следует использовать как оценку ускорения всего fullauto.
