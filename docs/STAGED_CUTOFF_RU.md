# Ступенчатое отсечение и безопасное продолжение fullauto

Новый расчёт PO:

```bash
mbs_po_gpu_float_ds --method po --backend cuda \
  --particle 1 125.9 78.1 --ri 1.3116 0 --wavelength-um 0.532 \
  --symmetry 2 6 --fullauto 0.04 --fullauto-theta-range 150 170 \
  --fullauto-cutoffs staged --orientation-pipeline --output column125 --close
```

Остальные параметры подбирает fullauto. `staged` оценивает результат без
отсечения как `F_N + B_m − F_m + O_k − B_k`, где F — fast, B — balanced,
O — без отсечения, `m=max(64,N/8)`, `k=max(64,N/64)` (целочисленно).
Каждая полная сумма входит в оценку ошибки как один независимый scramble;
восемь scramble учитывают дисперсию и корреляции всех поправок. Малые блоки
N<512 и глубины <6 остаются прямыми. Явные нативные пороги имеют приоритет.
По умолчанию `--fullauto-cutoffs auto` по-прежнему использует balanced.

На RTX 3080 Ti для одинакового ограниченного раунда когерентных буллитов
199,5 и 316,2 мкм получено 2,02× и 1,95× с конвейером. Это не измерение
времени достижения 4%: тестовые решения имели ошибки примерно 10,5% и 27%.
Максимальная наблюдаемая разность со схемой balanced по всем элементам —
0,158% и 0,311% M11. Эти разности не являются доверительной границей.

## Продолжение старого auto-чекпоинта

Нельзя просто заменить старый `--fullauto-cutoffs auto` на `staged`: это
изменяет идентичность обычного запуска. После численной сертификации точной
пары бинарников сохраните **все исходные физические аргументы**, добавив:

```text
--fullauto-resume-compatible /полный/путь/к/бинарнику_идентичности
--fullauto-cutoff-upgrade staged
--fullauto-dispatch-pipeline on
```

Если `--fullauto-resume-compatible` уже был задан, его исходный путь
сохраняется: это бинарник, хеш которого входит в идентичность чекпоинта.
Принимается только сохранённый физический target `off`, исходная политика
`auto`, отсутствие явно заданных нативных порогов и проверенная совместимость
бинарников. Геометрия, показатель преломления, диапазон, ориентации, точность
и другие физические параметры остаются прежними.

Готовые итоговые блоки сохраняют ключи и значения. Новые сырые источники
staged получают отдельные ключи, а оценки дисперсии при выборе φ — отдельную
идентичность пилота. Незавершённая старая транзакция не подменяет сырой fast
результатом balanced. Интегралы и матрицы используют одинаковые пять знаков.
Переход отмечается в `cutoff_upgrade.json`.

`--fullauto-dispatch-pipeline on` меняет исполнение только новых нативных
запросов, сохраняя ключи старой выборки. Его применяют после численного
сравнения старого исполнения и нового исполнения с конвейером. В статусе
`pipeline` — фактический режим, `saved_pipeline` — режим сохранённой выборки.
Сам по себе этот флаг не является доказательством численной совместимости.

Чекпоинт нужно зафиксировать после атомарной публикации, проверить его
контрольные суммы и сохранить резервную копию. Утилита
`scripts/check_fullauto_checkpoint.cpp` проверяет формат и контрольные суммы
потоковым чтением, не восстанавливая гигабайты данных на диск. После запуска
контроллер дополнительно проверяет идентичность и происхождение источников.

При обновлении очереди работающий процесс остаётся на прежнем бинарнике.
Менять следует только записи будущих задач; runner перечитывает manifest
между задачами. Для новой задачи используйте `staged` и `--orientation-pipeline`,
а не флаги миграции старого чекпоинта.
