# Упакованные промежуточные блоки fullauto

В обычном формате каждый завершённый блок создаёт каталог `jobs/<идентификатор>` и несколько файлов. Журнал `completed_jobs.journal` ускоряет поиск блоков, но **не заменяет их матрицы, интегралы и зависимости**. Поэтому старый `compact_v1` не ограничивает расход inode — записей файловой системы, необходимых для отдельных файлов и каталогов.

Новый формат `sharded_jobs_v1` сохраняет содержимое завершённых блоков в каталоге `job_packs`: не более 256 файлов с последовательной дописью на один каталог результата. Число блоков увеличивает размер этих файлов, а не количество inode. Открытые задания временно используют прежние каталоги. Итоговые DAT, параметры, снимки раундов и контрольная точка адаптивного алгоритма остаются обычными файлами.

Это изменение хранения, а не оценки точности. Оно не меняет ориентации, веса, порядок усреднения, матрицы, критерии сходимости или граф зависимостей. Оно не означает, что весь расчёт станет быстрее: скорость нужно измерять на конкретном диске и характере заданий.

## Включение и продолжение

На бинарнике с поддержкой формата режим включается так:

```bash
MBS_FULLAUTO_PACK_JOBS=1 /полный/путь/mbs_po_gpu_float_ds <прежние аргументы fullauto>
```

Переменная относится только к хранению и исключена из оптической идентичности контрольной точки. Остальные переменные `MBS_*` сохраняют прежнюю проверку. Файл `job_pack_format.txt` запоминает режим; при последующем запуске достаточно прежней команды. Значение `MBS_FULLAUTO_PACK_JOBS=0` отключает упаковку **новых** блоков; уже упакованные блоки продолжают читаться без распаковки.

Новая версия читает смешанный каталог: часть блоков может быть в `jobs`, часть — в `job_packs`. Старый бинарник без поддержки формата нельзя назначать такому каталогу до распаковки.

## Перевод существующего кэша

Сначала остановите **и очередь, и вычислительный процесс**. Иначе очередь, ожидающая свободных inode, может автоматически запустить старый бинарник во время перевода. Сам инструмент дополнительно требует исключительную блокировку `controller.lock` и откажется работать при активном контроллере.

```bash
c++ -std=c++11 -O2 -pthread tools/fullauto_pack_jobs.cpp -o fullauto_pack_jobs
./fullauto_pack_jobs /абсолютный/путь/результата
```

Для ограниченной первой партии можно передать максимальное число заданий:

```bash
./fullauto_pack_jobs /абсолютный/путь/результата 1024
```

Инструмент пропускает незавершённые задания и печатает прогресс каждые 256 блоков. Прерывание безопасно: подтверждённые записи остаются доступными; исходная копия удаляется только после проверки записи. После перевода запускайте проверенный новый бинарник с прежними аргументами и тем же каталогом результата. Упаковка сама не даёт разрешения на смену оптической версии: обычная проверка совместимости бинарников остаётся обязательной.

## Почему данные сохраняются при обрыве

1. Упаковывается только завершённый, неизменяемый блок.
2. Запись содержит прежние байты всех его файлов, имена и контрольные суммы. Ссылки и специальные файлы внутри задания отклоняются.
3. Заголовок, содержимое и завершающая запись сбрасываются на диск. Для нового архива сбрасываются также каталоги, содержащие его имя.
4. Содержимое архива повторно читается и сравнивается с исходными файлами. Затем подтверждённая граница архива записывается в два отдельных блока по 4 КиБ: сначала один блок со сбросом на диск, затем второй с отдельным сбросом. Только когда обе копии границы подтверждены, исходные файлы удаляются.
5. После обрыва любые байты за подтверждённой границей игнорируются, даже если размер файла уже вырос, а заголовок или хвост новой записи записался частично. Ранее подтверждённые записи доступны. Порча одного блока границы после удаления оригинала не скрывает последний блок расчёта: второй хранит ту же последнюю границу. Порча обеих копий либо данных внутри подтверждённой границы вызывает явную ошибку.
6. Если запись уже подтверждена, а удаление оригинала прервалось, оставшиеся файлы сверяются и удаляются при повторной упаковке. Повторной оптической работы не требуется.

Журнал обнаружения остаётся ускорителем. Даже если его последняя допись не успела сохраниться, блок обнаруживается по подтверждённой записи архива. Матрицы и зависимости проверяются перед использованием как прежде. Внешнее изменение архива сбрасывает доверие к кэшу контрольных сумм; штатная проверенная допись не сбрасывает кэш неизменённых старых блоков.

Индекс использует 16 байт на ячейку хеш-таблицы. Для 2,5 млн блоков тест занимает около 64 МиБ; его общий кэш ограничен 128 МиБ, кэш метаданных отдельных блоков — 8 МиБ. Одна упаковываемая запись ограничена 64 МиБ. Более крупный блок остаётся обычными файлами; расчёт продолжается, а исключение фиксируется событием `checkpoint_pack_oversize_retained`. Ошибки записи и контрольных сумм таким исключением не считаются и не подавляются. Во время сборки записи одновременно могут находиться в памяти исходные байты, упакованная копия и буфер проверки — примерно до трёх размеров записи, помимо индексов.

## Просмотр старым инструментом или возврат к обычным файлам

Файлы внутри `jobs` доступны новому контроллеру по прежним логическим путям, но обычный Python-скрипт или файловый менеджер не читает их из архивов автоматически. Для таких инструментов выполните под той же блокировкой:

```bash
./fullauto_pack_jobs /абсолютный/путь/результата --unpack
```

Распаковка сохраняет архивы, не перезаписывает отличающиеся файлы и восстанавливает содержимое байт в байт. Для неё снова нужны свободные inode и место. Чтобы после распаковки новые задания оставались обычными файлами, задайте `MBS_FULLAUTO_PACK_JOBS=0`. Старую версию бинарника можно использовать только при выполнении её обычных требований к совместимости контрольной точки.
