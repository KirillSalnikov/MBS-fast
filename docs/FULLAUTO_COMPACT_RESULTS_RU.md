# Компактный каталог результатов PO и GO

Новый формат включается явно: `--fullauto-layout compact`. Он одинаков для
физической (`--method po`) и геометрической (`--method go`) оптики. Пока это
опция для новых запусков: старые очереди, скрипты мониторинга и существующие
каталоги сохраняют прежний формат. Перемещать работающий расчёт вручную нельзя.

К обычной команде fullauto достаточно добавить:

```sh
--fullauto-layout compact --checkpoint --output ./particle_result
```

Примеры (размеры и длина волны в мкм, допуск — доля):

```sh
mbs_po_gpu_float_ds --method po --backend cuda --particle 1 10 5 \
  --ri 1.3116 0 --wavelength-um 0.532 --fullauto 0.04 \
  --fullauto-theta-range 150 180 --fullauto-layout compact \
  --checkpoint --output ./po_result --close

mbs_po_mpi --method go --backend cpu --particle 1 10 5 \
  --ri 1.3116 0 --wavelength-um 0.532 --fullauto 0.04 \
  --scattering-grid 0 180 1 180 --phi-points 1 \
  --fullauto-layout compact --checkpoint --output ./go_result --close
```

Параметры `--particle` сохраняют обычный смысл выбранного типа геометрии;
этот режим меняет расположение файлов, а не размеры частицы и не физику.
GO fullauto использует CPU и конечные телесноугловые ячейки; он не интерполирует
дельта-вклады и не превращается в CUDA PO от выбора нового каталога.

```text
particle_result/
├── config.json
├── status.json
├── latest -> results/round_14_<digest>/
├── results/
│   └── round_14_<digest>/
│       ├── mueller_bins.dat
│       ├── pole_contributions.dat
│       ├── integrals.tsv
│       ├── accuracy.json
│       ├── config.json
│       ├── angles.csv
│       ├── accuracy_by_angle.csv
│       ├── orientation_budget.csv
│       ├── matrix_schema.json
│       └── manifest.fnv
├── work/
│   ├── fullauto_checkpoint.bin
│   ├── run.log
│   └── ... внутренние файлы контроллера ...
└── archive/
    └── snapshots-<timestamp>.tar.zst
```

Номер раунда сопровождается отпечатком содержимого: повторный раунд после
восстановления/изменения глубины не перезаписывает другой результат. `latest`
переключается атомарно только после записи всех файлов снимка. Читателю,
открывающему несколько файлов, следует один раз разрешить ссылку `latest` и
далее читать выбранный каталог. Архивирование выполняйте без параллельных
читателей старых снимков.

## Что читать

* `latest/mueller_bins.dat`: неизменённые численные значения и стандартные
  столбцы DAT. Для **GO** это плотности в конечных телесноугловых ячейках.
  Для **PO**, несмотря на единое имя, это значения угловой матрицы на полной
  выходной сетке, включая интерполированные строки; это не интегралы по ячейкам.
* `latest/angles.csv`: происхождение каждой строки PO (опорная, проверочная,
  интерполированная) или ячейки GO, оценки ошибок и значения элементов.
* `latest/pole_contributions.dat`: для GO две интегральные матрицы δ-вкладов
  строго при 0° и 180°, отдельно от плотностей конечных ячеек. Для PO файл
  содержит пометку `not_applicable`, без фиктивных нулевых δ-матриц.
  `pole_status.json` для GO различает проверенную положительную массу и
  «ноль наблюдался, отсутствие вклада не доказано».
* `latest/integrals.tsv`: интегральные характеристики именно этого снимка,
  если они вычислены. Их наличие отмечено в `accuracy.json`; отсутствие не
  заменяется нулями или интегралами другого раунда.
* `latest/accuracy.json`: оценка опубликованной матрицы, контракт точности,
  политика финальных проверок, подбор глубины, итоговые проверки, если они
  выполнены. Пропущенная проверка не считается пройденной. Статистические
  оценки по отдельным углам не являются гарантией одновременной точности
  всей матрицы или физической точности метода.
* `status.json`: текущее состояние контроллера, исполняемый этап, время
  обновления, режим восстановления и ссылка на последнюю матрицу. Ошибка
  предыдущей матрицы не является ошибкой незавершённого нового раунда.
* `config.json`: запрошенные параметры, эффективная команда рабочего процесса
  и выбранное состояние. Копия внутри снимка фиксируется вместе с матрицей.

До первой полной сборки `latest` отсутствует. Пилот подбора глубины не выдаётся
за готовую матрицу. Между полными сборками меняется `status.json`, а `latest`
остаётся на последнем опубликованном результате.

## Рабочие блоки, журнал и восстановление

Для новых запусков по умолчанию действует рабочее хранилище `memory`:
внутренние матрицы и параметры блоков находятся в памяти/временном хранилище,
а не в миллионах отдельных постоянных файлов. `--checkpoint` включает
периодический общий файл `work/fullauto_checkpoint.bin` (по умолчанию 300 с).
Интервал можно явно задать через `--fullauto-checkpoint-seconds SECONDS`.
Это общий проверяемый снимок восстановления, **не сжатый архив каждого блока**.
Новый формат каталогов не меняет его двоичный формат и математический алгоритм.

Общий журнал контроллера — `work/run.log` (JSON Lines). Рабочие диагностические
файлы и индекс старого режима остаются внутри `work/`; здесь нет обещания,
что legacy-хранилище стало одним журналом или автоматически сжалось.
`--fullauto-storage legacy` сохраняет старый механизм постоянного кэша внутри
`work/`. Для сокращения числа файлов предпочтителен режим памяти.

Для восстановления повторите **ту же команду**, с тем же внешним `--output`
и `--fullauto-layout compact`. Не указывайте `--output .../work`: контроллер
сам выбирает этот каталог. Без `--checkpoint` (либо при явном интервале 0)
последняя опубликованная матрица сохранится, но продолжение вычислений после
завершения процесса не гарантируется. Проверка совместимости бинарника и
параметров остаётся прежней.

Пока не поддерживается `--fullauto-refine-window` вместе с compact: импорт
старого углового окна оставлен в прежнем формате, чтобы не менять граф
восстановления действующих задач.

## Архивирование старых опубликованных снимков

После остановки/завершения контроллера:

```sh
python3 scripts/archive_fullauto_results.py ./po_result
python3 scripts/archive_fullauto_results.py ./po_result --apply
```

Первая команда только показывает выбор. Вторая создаёт сжатый архив zstd,
распаковывает поток для проверки SHA-256 всех файлов, повторно проверяет
оригиналы и только потом удаляет старые каталоги снимков. Последний и минимум
один предыдущий снимок остаются открытыми. Для gzip без установленного zstd:

```sh
python3 scripts/archive_fullauto_results.py ./po_result --apply --compression gzip
```

Утилита берёт ту же блокировку, что контроллер, поэтому работающему расчёту
не удалит данные. Она не трогает `work/`, чекпоинт, блоки, пилоты и индексы
восстановления. Архивирование не запускается автоматически в горячем цикле.
Пилоты режима памяти входят в общий чекпоинт при его сохранении, поэтому
отдельный пустой `pilots.tar.zst` не создаётся.

Для просмотра архивных снимков распакуйте архив в отдельный каталог:

```sh
mkdir restored
zstd -dc ./po_result/archive/snapshots-TIMESTAMP.tar.zst | tar -xf - -C restored
```

Это восстанавливает опубликованные результаты, **не** заменяет вычислительный
чекпоинт. Не удаляйте `work/`, если нужно продолжить расчёт.


## Завершение fullauto по умолчанию

Для PO и GO достаточно одного успешного рабочего прохода. Финальные
пересчёты по умолчанию выключены: `--fullauto-final-checks off` больше не
требуется писать. Для расширенного аудита укажите `--fullauto-final-checks on`.
Он не включает второй успешный рабочий проход автоматически. Повторы задаются
явно через `--convergence-passes N` или `controller.stable_passes` в конфигурации.
Конфигурация, которая не задаёт этот ключ, не меняет один проход по умолчанию.

Явные `--fullauto-final-audit on` и `--fullauto-physics-audit on` также
включают финальные проверки, если общий переключатель не задан. Явное
`--fullauto-final-checks off` имеет приоритет над отдельными аудитами.
Стартовый подбор глубины, восемь независимых наборов, рабочие проверки
элементов, отношений и устойчивости сохраняются. В PO сохраняется проверка
интерполяции. Пропущенные финальные проверки помечаются как невыполненные;
их отсутствие не является подтверждением физической точности.

Новый режим применяется при запуске нового бинарника. Уже работающие процессы
не меняются. Завершённые результаты с другой политикой проверок не переписываются.
