Fullauto: локальные бюджеты и проверяемая точность

Программа сама выбирает параметры усреднения. Python нужен только для независимого аудита и графиков. Значение --fullauto .01 означает допуск 0,01: статистические ошибки элементов нормируются на M11; ошибки Mij/M11 измеряются в абсолютных единицах отношения. Например, допуск 0,01 для M12/M11 не означает относительную ошибку 1% от малого M12.

Запуск

bin/mbs_po --method po --backend cpu \
  --particle 1 10 6 --ri 1.3116 0 --wavelength-um .532 \
  --max-reflections 12 --beam-cutoff .001 --threads 4 \
  --fullauto .01 --fullauto-theta-range 0 25 \
  --output results/auto

Для файла произвольной формы используйте --particle-file shape.particle. Без явной --symmetry fullauto сначала использует полную меру SO(3), затем проверяет вращательные симметрии самой геометрии. Заголовок файла не считается доказательством симметрии. Если проверка не проходит, сохраняется полная область вращений. Мера Haar — равномерная мера вращений: cos(β) равномерен на [−1,1], α и γ равномерны на [0,2π). Для встроенной правильной призмы сохраняется её известная симметрия. Зеркальное сокращение дополнительно проверяется геометрически и численно.

Разделение допуска

Интерполяция получает EPS/4. Для внутренней оценки численной подготовки аналитических средних резервируется EPS/64, когда контрольные компоненты включены. Проверенное зеркало получает EPS/256; проверенные вращения — ещё EPS/256. Автоматически выбранные отсечения получают EPS/8. Неиспользуемые резервы возвращаются статистике. Остаток получает статистика. При недостаточной точности аналитических средних режим auto отключает контрольные компоненты и считает полное физоптическое поле.

Оценки статистики точечные, по восьми независимым Owen-scrambles. Это не одновременная гарантия на всём диапазоне и не оценка расхождения физоптики с ADDA. Глубина n остаётся заданной пользователем. Явные отсечения сохраняются; автоматические отсечения проверяются относительно полного расчёта без них при том же n.

Многоуровневая оценка

Для цели n=12 используются глубины 8, 10, 12. Для меньших n повторяющиеся глубины исключаются. Оценка имеет вид

E[M12] = E[M8] + E[M10 − M8] + E[M12 − M10].

Здесь M12 в формуле означает всю матрицу при глубине 12, а не её элемент M₁₂. Разности получают одинаковые ориентации внутри каждой пары. Число точек выбирается отдельно для основной оценки и поправок. В итоговой статистике используются суммы по каждому seed, поэтому фактическая совместная изменчивость уровней учитывается.

Для выпуклой частицы программа проверяет совместную трассировку глубин. Она сохраняет пучки верхней глубины и считает два полных когерентных поля. Все перекрёстные члены внутри каждого поля сохраняются. Если относительные выходные пороги зависят от различающихся максимумов пучков, нижний набор подготавливается отдельно. Вогнутые частицы, агрегаты и относительное отсечение ветвей используют самостоятельные трассировки.

Почему разные N требуют отдельной проверки интерполяции

У соседних углов с различными префиксами Sobol различается статистический шум. Его нельзя считать ошибкой геометрической интерполяции. Поэтому фактическая матрица и её статистика используют собственные N каждого угла, а интерполяционный остаток проверяется на одинаковых префиксах в локальном окружении интервала.

Используется непрерывный с непрерывной первой производной кусочно-кубический интерполятор. Производная в узле получается из локального полинома по четырём соседним узлам. Два конца интервала используют совместно не более пяти узлов. Оператор линейный по данным: каждый seed интерполируется отдельно, после чего оценивается разброс. Обычный раунд проверяет середины интервалов. Финальная независимая проверка использует все запрошенные θ при числе строк до 4097; на больших сетках — четверти интервалов.

На небольших сетках локальные группы могут тратить больше времени на запуск работников, трассировку и сборку файлов. Поэтому режим auto сохраняет общий N, когда число запрошенных θ × φ не превышает 256. На остальных сетках он дополнительно сравнивает модель стоимости локальных групп с общим бюджетом. Принудительный on предназначен для измерений и не гарантирует ускорения.

φ и аналитические контрольные компоненты

φ — число азимутов наблюдения для каждой ориентации. α — самостоятельный третий угол вращения, заданный третьей координатой Sobol. Увеличение φ дополнительно усредняет азимут; fullauto выбирает его по стоимости и разбросу. Если густой независимый пилот значительно расширил рабочую θ-сетку, φ повторно сравнивается на представительных рабочих углах и целевой глубине. Явное --phi-points фиксирует φ.

Контрольная переменная — случайный компонент C с известным средним μ. Для любого элемента матрицы используется оценка Y + b(μ − C). Коэффициент b выбирается на обучающих seeds и принимается только при снижении дисперсии минимум на 30% на отдельной проверочной выборке. Производственные seeds не участвуют в подборе. Отражённый компонент и теневая апертура дают две такие переменные. Для M11 исходные коэффициенты равны 1; для остальных элементов — 0. Поэтому поляризационная поправка включается только после измеренного выигрыша.

Нормированные элементы

Mij/M11 считается как отношение средних, а не среднее отношений отдельных seeds. Для статистического интервала используется метод Филлера с совместной ковариацией Mij и M11. Если знаменатель определён недостаточно хорошо, ограниченный интервал получить нельзя и расчёт продолжает уточнение. Интерполяционная проверка отношений также использует парный разброс.

Память и восстановление

Работники регулируют размер пакета подготовленных ориентаций по измеренному расходу памяти. Совместные глубины учитывают два подготовленных набора; при перекрытии CPU/GPU одновременно учитываются два пакета. На GPU используется существующий подбор размера пакета дифракции. Память не должна хранить все ориентации сразу.

В adaptive_checkpoint.tsv сохраняются сетка, N, коэффициенты, раунд и проверочные состояния. Записи обновляются атомарно с fsync. Пара PID/время рождения процесса и идентификатор загрузки системы защищают от совпадения PID после перезапуска. Завершённые блоки и их зависимости проверяются по контрольным суммам. Незавершённый блок считается заново. Повторный запуск полностью завершённого расчёта проверяет результаты и ничего не пересчитывает.

scripts/run_fullauto_service.sh mbs-case-01 /absolute/path/bin/mbs_po \
  /absolute/path/run.log --method po --backend cpu \
  --particle 1 10 6 --ri 1.3116 0 --wavelength-um .532 \
  --max-reflections 12 --fullauto .01 --output /absolute/path/result

Этот launcher устанавливает пользовательский systemd-сервис и сохраняет точные аргументы. Он не выбирает численные параметры. Сервис переживает разрыв SSH; включённая служба может возобновиться после загрузки сервера. Ошибки ввода и выходы «нужно больше выборок»/«не прошла физическая проверка» не перезапускаются бесконечно.

Файлы для проверки

  • orientation_budget.csv: реальные N по θ и уровням.
  • all_mueller_confidence.csv, normalized_mueller_confidence.csv: статистические оценки.
  • theta_validation.csv: проверка интерполяции.
  • independent_final_validation.json: независимый финальный контроль.
  • depth_sharing_verification.json: проверка совместных глубин.
  • physics_validation.json: чувствительность к глубине и отсечениям.
  • precision_contract.json: границы утверждения о точности.
  • jobs/: все матрицы, параметры, логи и зависимости.

Независимый аудит: python3 tests/audit_fullauto.py results/auto --dense. Он заново восстанавливает суммы уровней, статистику и интерполяцию из исходных матриц. Для локальных бюджетов ошибка интерполяции проверяется на согласованных префиксах; статистика фактической оценки проверяется отдельно.

Автоматический подбор ресурсов и отсечений

--fullauto-resources auto включён по умолчанию. На коротком расчёте программа сравнивает число потоков CPU и максимальное число ориентаций в пакете. Сравнение всех 16 элементов матрицы должно пройти порог 10⁻⁷ относительно M11. Размер сохраняемого блока оценивается по времени запуска и нативных фаз: цель — не более 5% накладных расходов и примерно 120 секунд вычисления на блок, в пределах 4096…1048576 и лимита N. Это модель стоимости, а не доказательство оптимальности. Явные threads, orientation-chunk и fullauto-orientation-block имеют приоритет. Нативное ограничение пакетов по RAM и VRAM продолжает действовать; для параллельных работников RAM разделяется.

--fullauto-gpus auto сравнивает видимые GPU, оставляет численно эквивалентные карты без большого замедления и распределяет восемь seed через очередь: свободная карта получает следующую работу. CUDA_VISIBLE_DEVICES ограничивает доступные карты. Без этого флага сохраняется карта 0. Сервисы других приложений программа не останавливает.

--fullauto-rotation-symmetry auto проверяет взаимно однозначное соответствие полных ориентированных граней после поворотов вокруг оси z частицы и поворота на 180° вокруг x. Затем явно трассирует эквивалентные ориентации на отдельных seed и сравнивает всю матрицу. У несовпадающих или иначе ориентированных форм сокращение не применяется. Явный --symmetry остаётся пользовательским утверждением и имеет приоритет.

--fullauto-cutoffs auto без явно заданных порогов сравнивает off, safe, balanced, fast. Время учитывает потерю совместной трассировки глубин при отсечении ветвей. Кандидат должен проходить EPS/8 по парным разностям всех элементов и отношений и давать не менее 10% выигрыша в пилоте. Перед завершением выбранный вариант проверяется на новых seed и до 65 представительных θ. При отказе программа переключается на off и продолжает адаптацию. Это точечная статистическая проверка, не строгая оценка всех редких траекторий или всего непрерывного углового диапазона. Явные пороги не заменяются.

--fullauto .01 --fullauto-gpus auto

Файлы решений: resource_calibration.json, rotation_verification.json, cutoff_calibration.json, automatic_cutoff_validation.json. execution_tuning.tsv сохраняет точный выбор для восстановления без повторного подбора. Для контрольного расчёта используйте fullauto-resources off, fullauto-rotation-symmetry off, fullauto-cutoffs off и cutoff-profile off.

Для численной эквивалентности настройки ресурсов и GPU зарезервирован EPS/1024; порог пилотного сравнения равен min(10⁻⁷, EPS/1024). Автоматическое вращательное сокращение не применяется к агрегатам или граням с специальными флагами видимости.

Когда подбор окупается

До перебора потоков и пакетов программа измеряет время нативных фаз и оценивает работу первой производственной серии. Перебор выполняется, если возможная экономия 25% покрывает оценку стоимости дополнительных пилотов. При короткой работе сохраняются исходные потоки и пакеты; размер сохраняемого блока всё равно можно оценить по уже выполненному пилоту. Для отсечений число точек пилота ограничено 2048 на seed. На короткой задаче дополнительные профили пропускаются, если прогноз экономии меньше их стоимости; тяжёлый базовый пилот (от 30 секунд суммарной работы) сохраняет полный перебор. Эти пороги — эвристики по измеренному времени, а не гарантия оптимального режима.

Финальный аудит отсечений начинает с независимой выборки не больше max(N_min, min(N_pilot,4096)) и производственного N. Если оценка ошибки выше EPS/8, выборка удваивается до трёх попыток и лимита N. Для этой малой разности не требуется сразу повторять всё производственное N.
