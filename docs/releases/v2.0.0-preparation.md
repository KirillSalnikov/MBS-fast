# MBS-fast 2.0 preparation

This records integration work, not an already published `v2.0.0` release.
The version tag and final release notes must follow the full release checks.

## Integrated changes

- The 40 fullauto commits after `main` at `1d7d3d7`, through `987e51e`:
  durable output/recovery, corrected pointwise acceptance, bounded work,
  matched interpolation residual budgets, common-phi checks, worker reuse,
  source/index I/O and progress reporting.
- `fix/go-fullauto-mirror`: `790c0df` reconstructs supported mirror partners;
  `14781ce` adds explicitly audited GO balanced cutoffs. GO defaults remain
  documented separately from PO.
- `codex/integrals-only`: `496ceef` and `5ceea1f`, exposing the final name
  `--extinction-only` for convex CPU/Hammersley forward extinction.
- Selected changes from `codex/validated-po-optimizations-20260907`:
  direction-independent multisize Jones phase caching and VRAM guards from
  `290b112`, and complete-orientation aperture fallback from `c26b9d4`.
  Current guarded vertex-phase arithmetic is retained. The old streaming-edge,
  adaptive-phi and mean-only FFT experiments are not imported.
- README and maintained Russian/English fullauto guides, standalone Russian
  HTML, and both typeset manuals now lead with automatic operation and explain
  Haar/Sobol sampling, analytic controls, Fresnel moments, depth/cutoff coupling,
  pointwise uncertainty, interpolation provenance and recovery.
- Strict C++11/warning cleanup, including a formerly unsequenced read/increment
  of the angular-audit metadata group counter. The increment is now a separate
  statement; numerical sample selection is unchanged.

The separate uncommitted resident-tracing/host-memory experiments in the
original development checkout are not part of this integration.

## Checks and commands

```bash
make test MBS_BUILD_JOBS=2
make test_fullauto_release
make test_sanitize MBS_BUILD_JOBS=2
make docs
# On a CUDA host:
MBS_CPU=/path/to/reference MBS_GPU=/path/to/gpu_binary \
  bash tests/run_cuda_release_gate.sh
python3 tests/regression_multik_phase_cache.py \
  --binary /path/to/gpu_binary --particle examples/cube.particle
python3 tests/test_cuda_aperture_fallback.py \
  --binary /path/to/gpu_binary --output /new/validation/directory
```

The release CLI gate includes executed argument-validator coverage as well as
real numerical runs and rejection cases. A name appearing only in help is not
sufficient. The fullauto integration target checks separate residual budgets,
common phi, changed-support recovery, complete eight-seed prefixes, durable
execution progress, GO mirror/balanced and extinction-only.

A bounded fullauto run and a completed-run resume are compared for an identical
matrix and absence of new native jobs. This is a software recovery check at
20% tolerance; it is not proof that a large particle reaches 2%.

## Measured integration evidence, 2026-10-26

The isolated FP64 CUDA build used V100 (sm_70), CUDA 12.2, GCC 7, precise math,
LTO and two to four CPU threads in runtime checks. The existing production
binaries, queues and checkpoints were not replaced.

- The CPU/FP64 CUDA hardware gate passed, including coherent/incoherent and
  alternative kernel paths.
- Three-size cached/uncached/legacy comparisons passed for real and absorbing
  refractive indices. All 16 elements were compared relative to local M11.
- A generated 40-sided prism exercised unsupported-aperture fallback. Maximum
  all-element error divided by CPU M11 was `4.2882e-16` coherent and
  `2.4554e-15` incoherent. Every sample retained the entire orientation.
- GO mirror, audited balanced cutoffs and extinction-only integration tests
  passed on the merged CPU binary.
- The completed fullauto checkpoint resumed with identical output and no new
  optical jobs. The residual and progress probes passed.
- The complete `make test MBS_BUILD_JOBS=2` passed on the final CPU sources,
  including fullauto integration and the CLI matrix (448/448 checks, 73/73 real
  runs, 374/374 expected rejections). The strict warning gate found zero project
  warnings; four compiler/toolchain warnings were classified separately.
- The ASan/UBSan CLI matrix passed 448/448 checks. Both PDF manuals and the
  standalone HTML guides were rebuilt; the PDF layout/error gate passed.

An additional arithmetic diagnostic compared the FP32 reduced profile with
FP64 on absorbing dust at 500 µm: maximum coherent all-element difference
divided by local M11 was `6.2724e-4` (0.062724%), and the maximum normalized-ratio
difference was `1.2553e-4`. This does not pass the `3e-5` threshold of the
reduced-versus-precise-FP32 regression when FP64 is substituted as its reference.
It is recorded as a precision limitation, not a passing FP32/FP64 equivalence
test or a guarantee for other sizes. Fullauto sampling intervals do not include
this arithmetic difference. The FP32 aperture-fallback check passed, but uses
the CPU fallback and is not evidence of general FP32 GPU accuracy.

Build logs, exact commands and outputs are retained in the integration artifact
`release2_merge_20261026`; a final release must identify its actual commit and
binary hashes, and must not substitute these development measurements for
unperformed tests on other supported GPU architectures/profiles.
