Два параллельных пути: CPU + (CPU → GPU)

Проверено 14 октября 2026 на epyc1: EPYC 7702, четыре V100-SXM2 16 GB, FP64, CUDA 12.2, sm_70. Ветка experiment/gpu-convex-resident-queue-20261014. Продолжение прямой GPU-цепочки из коммита 348c342.

6,704 → 4,437 с: ускорение 1,51× относительно CPU-трассировки. Относительно предыдущего прямого GPU-пути: 4,886 → 4,437 с, 1,10×. Это дополнительное уменьшение времени на 9,2%. Ни число ориентаций, ни физические параметры для ускорения не уменьшались.

Загрузка снята nvidia-smi с шагом 200 мс. «За жизнь процесса» учитывает все отсчёты между запуском и завершением соответствующего процесса. «Рабочая часть» исключает первые 0,5 с и последние 0,2 с каждого процесса. Это показатель активности устройства, а не заполнения всех CUDA-ядер.

Средняя загрузка всех четырёх карт за общее окно пакета у гибрида — 72,6%. Она ниже 84,4%, потому что задачи на GPU 0–1 завершаются раньше задач на GPU 2–3 и ждут конца измерения. Прямой GPU-путь имеет 75,7% за общее окно, хотя выполняет пакет медленнее. Поэтому критерием ускорения служит полное время, а не только процент загрузки.

Постоянные 100% не достигнуты. Остаются подготовка начальных пучков, выделение части буферов трассировки, синхронизации и завершение последнего CPU-блока. В финальных повторах рабочая часть гибрида в среднем занята примерно на 96%.

Как устроена двойная трассировка

  1. Общий список ориентаций. CPU-производитель и GPU-путь забирают непересекающиеся диапазоны через один защищённый курсор. Более быстрый путь получает больше диапазонов. Для каждой ориентации сохранены её углы и вес.
  2. CPU-путь. Восемь потоков полностью трассируют свою порцию, готовят пучки, затем отдельный управляющий поток отправляет их на GPU для дифракции. Его GPU-буферы принадлежат только этому потоку.
  3. GPU-путь. Два CPU-потока поворачивают геометрию и создают начальные пучки. GPU трассирует внутренние отражения и преломления, готовит выходные пучки и считает дифракцию. Сырые пучки этого пути остаются на GPU.
  4. Запас работы ограничен. Очередь вмещает до двух готовых CPU-блоков. В основном режиме в неё попадают уже рассчитанные частичные матрицы. Это освобождает большие массивы CPU-пучков сразу после их дифракции. Есть диагностический вариант, где очередь хранит подготовленные пучки, а их дифракцию запускает основной поток.
  5. Объединение. Главный поток последовательно складывает частичные матрицы, входную/выходную энергию и экстинкцию. Каждая ориентация принимается один раз. Интерференция пучков внутри ориентации сохраняется; между независимыми ориентациями, как и раньше, усредняются матрицы Мюллера.
  6. Повторное использование памяти. Буферы GPU-подготовки сохраняются между блоками в отдельном пуле для каждого потока и устройства. Обнуляются необходимые счётчики; память перевыделяется только при росте блока и освобождается при завершении потока. Буферы самой очереди трассировки ещё не все переведены на повторное использование.

В первом финальном повторе CPU обработал 3312 ориентаций на карту, GPU-путь — 13 072; доля CPU около 20%. Она определяется скоростью выполнения, а не заранее заданным процентом. CPU-блок растёт от пилотного размера по оценке памяти до максимума 256. Проверены максимумы 64, 128, 256 и 512; 256 оказался лучшим в короткой сравнительной серии. Простое накопление CPU-пучков без отдельного GPU-потребителя дало меньший выигрыш.

Точность и ограничения

Сверены все 16 элементов при каждом угле, отношения Mij/M11 и интегральные характеристики Cext, Csca, Cabs, Qext, Qsca, Qabs. Максимум |ΔMij|/M11: 3.28e-09; максимум относительного расхождения интегральных характеристик: 1.14e-09. На больших пакетах максимум |ΔMij|/M11 — 7.44e-10. Это проверка эквивалентности реализаций; она не устанавливает физическую точность PO или сходимость по ориентациям.

Проверены границы и полнота диапазонов: без повторов и пропусков. CPU/MPI-сборка и тест устойчивости топологии прошли. При поглощении, невыпуклой геометрии и некогерентном режиме остаётся прежний путь; его результаты также сверены.

Гибрид сейчас экспериментальный: когерентный PO, FP64, выпуклая частица без поглощения; ограничения резидентного GPU-трассировщика — до 16 граней, до 24 вершин пучка и n≤18. FFT, Карчевский, GO, FP32, вывод Jones, аналитические контроли и парная проверка глубины сохраняют прежнюю обработку. При переполнении лимитов резидентного блока весь блок пересчитывается прежним путём; частичный результат не добавляется дважды. Отказ дифракции CPU-производителя завершает рабочий процесс с ошибкой.

Это воспроизведение одного из измеренных пакетов. Полные исходные команды всех четырёх карт лежат в каждом command.json. Для четырёх карт запускаются четыре независимых процесса с CUDA_VISIBLE_DEVICES=0, 1, 2, 3; на каждой паре используется своя форма и два разных seed. Во второй призме H=501,2 / D=155,8 мкм, 877 θ × 1 φ; в первой H=446,7 / D=147,1 мкм, 11 θ × 8 φ. В обоих случаях λ=0,532 мкм, m=1,3116, n=14, balanced cutoff, Haar α и прежние симметрии.

Автоматическое включение гибрида в fullauto не добавлено. Его подбор точности, ориентаций, отражений и cutoff не менялся. Полный fullauto с этим конвейером ещё не измерялся, поэтому ускорение 1,51× нельзя переносить на всё время кампании. Производственные бинарники и чекпоинты сохранены; тестовые окна завершены, контроллеры 1878 и 1880 возобновлены.

Логи, бинарник и воспроизводимость

result_hybrid_ranges_rank0.tsv содержит для каждого блока путь CPU/GPU, начальный индекс, число ориентаций, число CPU-потоков, время подготовки/потребителя и сумму весов. Строки могут идти в порядке завершения: для проверки покрытия их нужно отсортировать по start. GPU hybrid summary печатает распределение ориентаций, максимальный запас, время ожидания последнего CPU-блока и заполненной очереди. При fallback метка GPU означает назначенный путь, а фактическое принятие отражено в логе GPU convex resident direct.

Времена двух параллельных ветвей перекрываются: суммы фаз не равны полному времени. Для сравнения скорости используйте wall time. Пул VRAM дополнительно пишет cached_MiB. Нового формата чекпоинтов внутри рабочего процесса нет; журнал диапазонов предназначен для аудита, а не самостоятельного восстановления.
