# Fullauto: запуск, математика и проверка результата

Руководство к объединённому коду для подготовки MBS-fast 2.0, 26 октября 2026.
Источники поведения: `src/FullAuto*.inc`, `src/FullAuto.cpp`, `src/CliOptions.cpp`.
Проценты в примерах относятся к численной погрешности внутри модели PO или GO.

## Самый короткий запуск

```bash
make -C cpu -j2
cpu/bin/mbs_po_mpi --method po --backend cpu \
  --particle 1 5 2 --ri 1.3116 0 --wavelength-um 0.532 \
  --fullauto 0.02 --output results/column_5um
```

`po` — физическая оптика; `cpu` — вычисление на процессоре. `--particle 1 L D`
задаёт правильный шестигранный столбик: L — длина вдоль его оси, D — диаметр
основания. Здесь L=5 и D=2 мкм. `--ri REAL IMAG` задаёт комплексный показатель
преломления. Длина волны и координаты частицы должны иметь одинаковые единицы.
`0.02` — допуск 2%. Каталог `--output` хранит матрицы, параметры и восстановление.

Не нужно добавлять Sobol, число φ, стартовые ориентации, коэффициенты аналитической
модели и отсечение только ради включения автоматики: контроллер задаёт их сам.
Это один процесс контроллера; не запускайте несколько MPI-контроллеров в одну папку.

Частица из файла с максимальным габаритом Dmax=5 мкм:

```bash
cpu/bin/mbs_po_mpi --method po --backend cpu \
  --particle-file examples/cube.particle --resize-dmax-um 5 \
  --ri 1.3116 0 --wavelength-um 0.532 \
  --fullauto 0.02 --output results/file_5um
```

Dmax — максимальное расстояние между вершинами. Оно отличается от длины столбика,
его диаметра основания и диаметра равновеликого шара. Данные о симметрии в файле
не считаются доказательством: сначала используется полная область ориентаций.

## GPU, конусы и подробная команда

Сборка FP64 для V100: `make -C gpu fp64 GPU_ARCH=70 -j2`.
Для RTX 3080 Ti используйте архитектуру 86, для RTX 4090 — 89.
Сборка `fp32` быстрее на потребительских картах, но её арифметическую погрешность
нужно проверить отдельно: статистический интервал Sobol её не измеряет.

```bash
# Вперёд: 0–25 градусов, один GPU.
CUDA_VISIBLE_DEVICES=0 gpu/bin/mbs_po_gpu_double \
  --method po --backend cuda --particle 1 100 50 \
  --ri 1.3116 0 --wavelength-um 0.532 \
  --fullauto 0.02 --fullauto-theta-range 0 25 \
  --output results/column_100_forward

# Назад: 170–180 градусов, два GPU одного контроллера.
CUDA_VISIBLE_DEVICES=0,1 gpu/bin/mbs_po_gpu_double \
  --method po --backend cuda --particle 1 100 50 \
  --ri 1.3116 0 --wavelength-um 0.532 \
  --fullauto 0.02 --fullauto-theta-range 170 180 \
  --fullauto-gpus 0,1 --output results/column_100_backward
```

Номера GPU отсчитываются после применения `CUDA_VISIBLE_DEVICES`.
Для двух независимых размеров запускайте два контроллера с разными каталогами
и непересекающимися списками GPU. Флаги старого multisize не совмещаются с fullauto.

Расширенный пример намеренно фиксирует часть параметров:

```bash
CUDA_VISIBLE_DEVICES=0 gpu/bin/mbs_po_gpu_double \
  --method po --backend cuda --particle-file examples/cube.particle --resize-dmax-um 5 \
  --ri 1.3116 0 --wavelength-um 0.532 \
  --fullauto 0.02 --fullauto-theta-range 170 180 \
  --max-reflections 8 --phi-points 4 \
  --fullauto-initial 512 --fullauto-min-correction 256 \
  --max-orientations 1048576 --threads 4 \
  --fullauto-rotation-symmetry off --fullauto-mirror off \
  --cutoff-profile off --fullauto-analytic-controls off \
  --output results/fixed_settings
```

| Флаг | Что меняет |
|---|---|
| `--max-reflections 8` | Фиксирует целевую глубину. Автопоиск 6…18 выключен. Финальная проверка может обнаружить недостаточную глубину. |
| `--phi-points 4` | Фиксирует число наблюдательных азимутов; поиск φ не заменит это значение. |
| `--fullauto-initial 512` | Начальное N на один seed, а не окончательное N. |
| `--fullauto-min-correction 256` | Минимальное число ориентаций поправки на один seed. |
| `--max-orientations 1048576` | Верхняя граница N; достижение границы не означает сходимость. |
| `--threads 4` | Явное число потоков; автоматический подбор не должен его переопределять. |
| `--fullauto-rotation-symmetry off` | Не искать сокращение области по вращениям тела. |
| `--fullauto-mirror off` | Не использовать зеркальное сокращение. |
| `--cutoff-profile off` | Фиксировать расчёт без отсечения; автоматический balanced с поправкой не включается. |
| `--fullauto-analytic-controls off` | Вычислять полную PO без аналитических контрольных компонент. |

Обычно короткая команда удобнее. Расширенный вариант нужен для воспроизводимых
сравнений и проверки одной настройки. Явное ограничение имеет приоритет, но
несовместимые режимы должны завершаться ошибкой, а не молча игнорироваться.

## Что означает требуемая точность

M — матрица Мюллера 4×4; она переводит падающий вектор Стокса в рассеянный.
θ — угол рассеяния: 0° вперёд, 180° назад. Для каждого проверяемого θ контролируются
все 16 элементов. Масштаб абсолютной ошибки Mij — M11 того же угла. Поэтому нуль
M12 не приводит к делению на M12. Дополнительно по умолчанию проверяются отношения
Mij/M11; их погрешность задаётся в абсолютных долях отношения.

Для каждого элемента и угла складываются его статистическая оценка, его оценка
интерполяции и фиксированные резервы. Максимум берётся **после** этого сложения:

$$E=\max_{\theta,j}\{e_{\mathrm{stat},\theta j}
+e_{\mathrm{interp},\theta j}+r_{\mathrm{fixed}}\}.$$

Отдельно проверяются непосредственно вычисленная и полная выходная матрицы.
Нельзя складывать максимальные статистическую и интерполяционную ошибки разных
элементов и выдавать это за реализованный критерий.
Интерполяционный допуск равен EPS/4: для 2% это 0,5%, для 1% — 0,25%.
Резервы зависят от включённых проверок глубины, симметрии, аналитики и исполнения.
Фактические значения записаны в файлах параметров и `pointwise_budget_production.csv`.

95%-интервалы здесь поточечные и статистические. Они не гарантируют одновременно
95% для всех углов, не доказывают отсутствие узкого пика между проверками и не
измеряют ошибку самой модели PO относительно точного электромагнитного решения.
Отключённая проверка обозначается как непроверенная, а не как нулевая ошибка.

## Последовательность работы

1. Проверить аргументы, геометрию, единицы и доступные ресурсы. Построить запрошенную
   сетку вывода и стартовую оценку N. Если есть совместимый чекпоинт, восстановить его.
2. Подобрать целевую глубину внутренних взаимодействий, если она не задана.
   На CUDA перед этим проводится короткая настройка исполнения и φ для пилота;
   полный подбор выполняется после выбора глубины.
3. Проверить допустимые симметрии. Обучить аналитические контрольные коэффициенты
   и проверить их на других seed. Выбрать φ и параметры исполнения по стоимости
   достижения допуска, а не только по времени одного малого запуска.
4. Вычислять опорные и проверочные θ, восемь независимых реплик и уровни поправок.
   Сохранять завершённые блоки; использовать прежние блоки для совпадающих запросов.
5. Оценить статистику, остаток интерполяции и устойчивость префиксов. Уточнять
   ориентации или θ там, где это требуется. Шумный остаток сначала получает больше
   парных образцов; новый опорный θ добавляется при подтверждённой структуре.
6. Опубликовать промежуточную матрицу и оценки. После прохождения рабочих критериев
   выполнить включённые независимые и физические проверки и сохранить итог.

`--fullauto-final-checks off` отключает финальные перепроверки. Это меняет объём
проверенного результата, а не делает пропущенные проверки успешными. По умолчанию
их сохраняют. Такой режим нельзя использовать с GO balanced, которому обязательна
проверка ошибки отсечения. При явном `--convergence-passes` число проходов сохраняется.

## Стартовое N и глубина n

N — число ориентаций **на одну** Sobol-реплику и уровень. Восемь реплик с N=512
означают 4096 ориентаций базового уровня; поправки имеют свои N.
n — максимальная глубина внутренних взаимодействий в трассировке.

По умолчанию coherent PO использует эмпирическую оценку по уже завершённым
расчётам, размеру, длине волны, диапазону θ, форме и допуску. Это только начало,
а не предсказанная гарантия сходимости. В реализации:

$$\begin{aligned}
s={}&8.5128934+2.0264267\log_2(1+L_{\max}/(8\lambda))\\
&+0.6416260\,I(\theta_{\max}>90^\circ)
+4.0403518\,I(\Delta\theta>90^\circ)\\
&+0.8222766\,I(\text{controls off})
-2.7035215\,I(\text{не столбик типа 1}).
\end{aligned}$$

$$N_{\mathrm{forecast}}=2^s(0.01/\mathrm{EPS})^2,\qquad
N_0=\operatorname{pow2up}\!\left(\max(512,N_{\mathrm{forecast}}/16)\right).$$

Lmax — наибольшее ребро в оценке геометрии; I — индикатор условия (0 или 1);
pow2up — округление вверх до степени двойки. До округления применяется предел,
связанный с `--max-orientations`. Коэффициенты модели получены по 234 записям,
73 уникальным когерентным конфигурациям; перенос на новую форму проверяется
последующей сходимостью. Формула со знаком «не столбик» отражает эти данные,
а не общий физический закон для произвольных частиц.

`--fullauto-initial-model xi` возвращает старый ориентир beta×gamma по мелкому
дифракционному шагу; он часто завышает старт. Явный `--fullauto-initial` заменяет
обе модели. Для GO и некогерентной PO применяется другой ограниченный старт,
связанный с оптической толщиной поглощения; GO без поглощения масштабно инвариантна.

Поиск n начинается с 6 и может поднять его до 18. Сравниваются n и n+2 на общих
ориентациях: сначала уменьшается шум разности, затем решается, нужно ли увеличивать
n. Старт пилота по умолчанию min(512,N0), независимый от большого производственного
N. Параметры: `--fullauto-depth-start`, `--fullauto-depth-max`,
`--fullauto-depth-pilot`, `--fullauto-depth-order`.
Неразрешённый пилот или достигнутый предел глубины не принимаются как успех.
`--max-reflections N` отключает поиск целевого n, но не обещает прохождение
включённого финального сравнения n/n+2.

## Усреднение Sobol и три угла Эйлера

Поворот задаётся R=Rz(α)Ry(β)Rz(γ). Для равномерного случайного положения частицы
нужна мера Хаара — равномерная мера на группе трёхмерных поворотов SO(3):

$$\langle M\rangle=\frac{1}{8\pi^2}
\int_0^{2\pi}\!d\alpha\int_0^\pi\!\sin\beta\,d\beta
\int_0^{2\pi}\!M(R,\theta)\,d\gamma.$$

Для полной области точки u,v,w из единичного куба превращаются в
cosβ=1−2u, γ=2πv, α=2πw. Равномерно раскладывать β без веса sinβ было бы неверно.
Sobol строит последовательность с равномерным покрытием куба; вложенное
перемешивание Owen с seed делает независимые рандомизированные реплики.
Это не независимые случайные точки внутри каждой реплики и не декартова
сетка Nα×Nβ×Nγ. Поэтому сравнение одного N Sobol с произведением трёх сеточных
размеров не означает такое же увеличение точности или ускорение.

Восемь seed используются для оценки неопределённости. Пусть Yr — целая оценка
матрицы из реплики r, включая связанные поправки. Тогда

$$\bar Y=\frac18\sum_{r=1}^8Y_r,\quad
s_Y^2=\frac17\sum_{r=1}^8(Y_r-\bar Y)^2,\quad
h_{95}=t_{0.975,7}\,s_Y/\sqrt8.$$

t — квантиль распределения Стьюдента, около 2,365. Для Mij/M11 учитывается
ковариация числителя и знаменателя и проверка разрешимости отношения; малый
шумный знаменатель не разрешается заменой на удобный нулевой интервал.
Данные половинных префиксов дополнительно проверяют устойчивость.

N растёт степенями двойки. Уже рассчитанный префикс используется повторно;
`--sobol-offset` в рабочих заданиях задаёт его продолжение. Производственные,
обучающие и проверочные seed разделены. Один seed не заменяет восемь реплик.

Sobol — наиболее практичный текущий вариант для наших неоднородных PO-интегралов
и локального уточнения: можно наращивать префикс и совместно считать разности
уровней. Это не доказательство превосходства над Лебедевым или разложением Вигнера
на любой форме. Их преимущества зависят от гладкости и симметрии конкретной задачи.

## Зачем φ, если уже есть α

α вращает частицу вокруг направления падающего света. φ задаёт азимут наблюдателя.
При полном усреднении по α дополнительные φ могут снижать дисперсию, сохраняя
математическое ожидание. В каждой ориентации это разные операции; для поляризационных
элементов также нужен корректный поворот базиса Стокса.

`--haar-alpha` добавляет третью координату Sobol. Fullauto PO использует её сам.
По мере увеличения числа ориентаций не требуется автоматически делать φ столь же
мелким, как в старой двухугловой сетке. Но φ=1 не гарантирует минимальное время:
дополнительные направления наблюдения используют уже трассированные пучки.
Контроллер выбирает компромисс «стоимость × дисперсия» и может уточнять φ локально.
`--phi-points N` закрепляет правило. `--sobol-seed 32768 SEED` относится к ручному
запуску; в fullauto используйте `--fullauto-initial 32768` для начального N.

Вращательная и зеркальная симметрии относятся к телу и проверяются отдельно.
Шестикратная симметрия столбика не даёт права делить лабораторное α или φ на шесть.
Для произвольной частицы без подтверждённой симметрии остаётся полная область.

## Что вычисляется аналитически

### Дифракция отдельного пучка

Плоский многоугольный выходной пучок даёт интеграл вида

$$F(\mathbf q)=\int_A\exp(i\mathbf q\cdot\mathbf x)\,dA.$$

Для постоянной амплитуды на плоской апертуре его можно свести к сумме по рёбрам.
При малой фазе и почти нулевых знаменателях используются устойчивые пределы и
моменты. Это аналитическое вычисление дифракции **для данной ориентации**;
оно не выполняет всего ориентационного усреднения. Комплексные амплитуды пучков
складываются когерентно до перехода к матрице Мюллера. В некогерентном режиме
складываются отдельные интенсивности: это другая физическая постановка.

### Аналитические контрольные компоненты

Пусть C(R,θ) — дешёвая физическая модель с известным средним μC(θ), а M — полная
PO. Контрольная переменная даёт оценку

$$\widehat M=\overline{M-bC}+b\mu_C.$$

b — коэффициент уменьшения дисперсии, обученный отдельно от производственной
выборки. При корректном μC вычитание и возврат среднего сохраняют ожидание.
Внутренние пути, затенение и интерференция, отсутствующие в C, остаются в M−bC.
Поэтому усреднить коэффициент Френеля и заменить им все отражения недостаточно.

Контроли включают самовклады отражающих граней и модель тени. Для M11 используются
их физические средние; поляризационные контроли и поворотные компоненты проходят
собственную проверку. Неподходящие компоненты отключаются после проверки по полной
PO: это допустимый отказ от ускорения, а не отказ от расчёта рассеяния.

### Моменты Френеля и фазовые средние

μ — косинус угла падения на грань, rs(μ), rp(μ) — коэффициенты Френеля двух
поляризаций. Отражательная способность R(μ)=(|rs|²+|rp|²)/2 зависит от μ.
Момент — интеграл этой функции с весом; например,

$$c_\ell=\frac{2\ell+1}{2}\int_0^1 R(\mu)P_\ell(\mu)\,d\mu,$$

где $P_\ell$ — полином Лежандра. В физических ядрах присутствуют также геометрические
и проекционные веса. Теорема сложения и разложение плоской волны позволяют
аналитически усреднить угловые фазовые множители, используя сферические функции
Бесселя. Общие моменты повторно используются для многих θ. Гладкие одномерные
интегралы Френеля, таблицы радиальных ядер и часть интегралов по рёбрам остаются
численными. Это аналитико-численный контроль, не замкнутое решение всех путей.

| Настройка | Смысл |
|---|---|
| `--analytic-facet-average` | Явно запросить аналитический контроль граней; fullauto умеет включать и проверять его автоматически. |
| `--analytic-shadow-control circular` | Контроль тени круглой апертурой с геометрически определённой площадью. Отличие от реальной формы остаётся в остатке. |
| `--analytic-mean-cache FILE` | Файл кэша средних для совпадающих параметров. В fullauto этот параметр можно оставить автоматике. |
| `--analytic-mean-threads N` | Потоки подготовки аналитического среднего; явное значение фиксируется. |
| `--fullauto-analytic-controls off` | Полная численная PO, без этих контролей. |

Для большой частицы подготовка среднего может стоить заметного времени и RAM.
Кэш экономит повторную подготовку; это не дополнительный физический эффект.
Режим GO и некогерентный режим не используют те же когерентные PO-контроли.

## Поправки по глубине и отсечению

Несколько уровней используют тождество

$$\mathbb E[M_{n_L}]=\mathbb E[M_{n_0}]
+\sum_{\ell=1}^{L}\mathbb E[M_{n_\ell}-M_{n_{\ell-1}}].$$

Это многоуровневая оценка: дорогие разности могут иметь меньшую дисперсию, чем
полная матрица, и потому требовать меньше ориентаций. Оба слагаемых разности
используют одинаковые ориентации. Где поддерживается, общая трассировка сохраняет
результаты для двух глубин. Разность берётся между матрицами полных когерентных
решений соответствующей глубины, а не между интенсивностями отдельно отброшенных
лучей. Ковариации учитываются через полную сумму внутри каждой из восьми реплик.

По умолчанию когерентная PO использует balanced с парной поправкой:

$$\widehat M=\overline{B}_N+\overline{(O-B)}_m.$$

B — расчёт с отсечением, O — без отсечения. Ориентации O и B в поправке совпадают.
Физическая цель остаётся O. Небольшой m экономит работу, пока дисперсия поправки
достаточно мала; в коде используются минимальные блоки и доля префикса.
Отдельный подбор пресетов по умолчанию больше не нужен. Время всё равно зависит
от числа пучков поправки и её дисперсии: гарантированного ускорения нет.

Явный `--cutoff-profile balanced` фиксирует пресет и не эквивалентен автоматической
схеме с O−B. Явные пороги также имеют приоритет. Для GO balanced применяется
отдельная проверка смещения относительно off, описанная в `GO_BALANCED.md`.

## θ, интерполяция и короткие раунды

Выходная сетка, опорные θ и проверочные θ — разные множества. Без внешней сетки
fullauto строит достаточно плотную сетку вывода из размера, λ и диапазона. Прямой
расчёт производится на адаптивном подмножестве. `--theta-grid-file FILE` фиксирует
именно углы вывода, но сам по себе не означает прямое вычисление каждой строки.

Локальная кубическая интерполяция I линейна по значениям матрицы при фиксированных
узлах. Проверяется остаток $\Delta=M(\theta)-I[M_{\mathrm{support}}](\theta)$ на одинаковых ориентациях. Это
позволяет сокращать общий ориентационный шум. Бюджет остатка теперь отдельный:
он не наследует максимальное N соседнего дорогого угла. При различных рабочих
φ для остатка обе стороны используют единое правило φ. Основной расчёт сохраняет
свои правила. Выборка остатка фиксируется до чтения значений, а затем уточняется
по неуспешной проверке.

Новый опорный угол начинается с обычного стартового бюджета. Полные уже готовые
префиксы восьми seed сохраняются. Планировщик ограничивает объём следующего раунда
по измеренной стоимости; ориентир 1800 рабочих секунд на GPU не является жёстким
сроком. Неделимый префикс, трассировка или чтение кэша могут занимать больше.

Важная проверка на реальных данных: для столбика 794,3×196,2 мкм, λ=0,532,
m=1,3116, участка 170,042–170,072°, восьми seed и N=512 на уровень остаточная
оценка составила 322,691% при смешанных φ=4/64 и 0,0329171% при общем φ=64.
Это снижение шума **проверочного остатка на этом участке**, не ошибка всей матрицы
и не измеренное ускорение всего расчёта. Уровни 14/16/18 считались без отсечения.

В полном DAT проверочный угол также может содержать интерполяцию, хотя для него
есть отдельный прямой расчёт. Для различения используйте `value_source` и
`point_type` в аннотированном CSV и `mueller_evaluated.dat`. Не заменяйте одни
значения другими постфактум без новой проверки принятого выходного оценивателя.

```bash
python3 -m json.tool results/column_5um/fullauto_status.json

```

После отключения повторите исходную команду тем же бинарником и в ту же папку.
Завершённые блоки загружаются; незавершённый блок может повториться. Чекпоинт
версии 6 хранит производственный и остаточный бюджеты, а также φ остатка.
Поддержано чтение старых схем, но совместимость бинарников проверяется отдельно.

один TSV чекпоинта без зависимых блоков.

при подтверждённой совместимости конкретной пары бинарников и вычислительных
профилей. Сам факт успешной сборки такой совместимостью не является.
Для нового допуска или окна используйте документированный режим
`--fullauto-refine-window A B EPS` и сохранённую исходную конфигурацию; не
редактируйте физические параметры существующего каталога.

Служба Linux может автоматически возобновлять процесс после перезагрузки:

```bash
scripts/run_fullauto_service.sh mbs-column cpu/bin/mbs_po_mpi \
  results/column_service.log --method po --backend cpu \
```

Этот скрипт устанавливает пользовательскую службу systemd и запускает её.
Он управляет процессом; численные решения остаются внутри программы.

## Память, загрузка GPU и границы метода

CPU трассирует и подготавливает пучки; CUDA вычисляет дифракцию и поддержанные
части трассировки. Постоянные рабочие процессы сохраняют CUDA-контекст и ограниченные
кэши. Готовые пакеты распределяются между GPU, проверка и сохранение данных
перекрываются с дальнейшей работой. Видеопамять занята пучками, угловыми буферами,
матрицами и рабочими областями; RAM — геометрией, подготовкой и кэшем блоков.

Загрузка GPU может падать при трассировке, сборке префиксов, проверке и I/O.
100% загрузки не является критерием ни правильности, ни минимального времени.
Большой пакет снижает накладные расходы, но повышает память и задержку публикации.
Контроллер ограничивает память и объём работы; OOM или исчерпание диска не являются
успешным завершением. Текущее время задания видно отдельно от возраста оценки.

## GO и extinction-only

```bash
cpu/bin/mbs_po_mpi --method go --backend cpu \
  --particle 1 100 50 --ri 1.3116 0 --wavelength-um 0.532 \
  --fullauto 0.02 --output results/column_go
```

GO — геометрическая оптика: α усредняется аналитически; конечные угловые ячейки
считаются напрямую, кубической PO-интерполяции нет. Полюсные дельта-вклады
сохраняются отдельно в `mueller_forward.dat` и `mueller_backward.dat`; это
интегральные массы, не значения гладкой диаграммы в градусной точке.

GO mirror по умолчанию выключен. Явное включение поддерживает непоглощающие
встроенные типы 1 и 10 с допустимыми симметриями; зеркальная пара восстанавливается
через (M+PMP)/2, P=diag(1,1,−1,−1), включая полюсные вклады. Это не простое
удвоение числа симметрий. Файловые формы и поглощение не принимаются как поддержанные.
Подробности: `GO_MIRROR.md` и `GO_BALANCED.md`.

`--extinction-only` — отдельный CPU-режим PO с Hammersley для выпуклой геометрии.
Он вычисляет экстинкцию по оптической теореме без угловой сетки матриц; не является
fullauto и не даёт полного интеграла рассеяния или точного альбедо. Примеры:
`EXTINCTION_ONLY.md`.
