Трассировка в два этапа: пересечение и оптика

Эксперимент 29 октября 2026, продолжение версии 9f3bd22. Итоговая экспериментальная сборка — v4. Проверки выполнялись на dima/GPU0 и epyc1/GPU1. Производственные расчёты, очереди и бинарники не переключались.

Получено ускорение на дроксталле с сохранением прежнего объёма очередей. Результат проверен в постоянном процессе fullauto на пяти независимых seed. Для столбиков эффект меньше и зависит от режима; универсального ускорения всех задач не заявляется. По умолчанию остаётся прежний трассировщик.

Как устроено изменение

Очередь — массив пучков одного уровня внутренних отражений. Рекурсия была заменена очередями ещё в прежней версии. Новое изменение разделяет обработку каждого уровня на два CUDA-ядра:

  1. Пересечение. Потоки находят полигон пересечения пучка с гранями. В следующую очередь записываются обрезанный контур, оптическое состояние родителя и номер целевой грани. Режим split использует один поток на пучок, split8 — группу из восьми потоков, проверяющих разные грани.
  2. Оптическое расщепление. Один поток обрабатывает одну готовую запись: рассчитывает отражение и преломление, базис поляризации, коэффициенты Френеля и фазу. Прошедший пучок записывается в выходной массив. Отражённый заменяет промежуточную запись на том же месте. Отсечённая ветвь получает отметку неактивной и пропускается на следующем уровне.

Исходный полигон родителя после пересечения больше не нужен для оптического расщепления: нужны его направление, базис, комплексная матрица Джонса, оптический путь и положение фронта. Обе дочерние ветви используют один обрезанный контур. Поэтому вместо копирования двух массивов вершин ядро читает общий контур, а отражённый пучок сохраняется на месте. За пределы ядра ссылки на временную геометрию не передаются.

В промежуточной версии было три массива: две очереди плюс полигоны пересечений. В испытании постоянного hybrid на epyc1 дополнительный массив уменьшал доступную выходную ёмкость и вызывал штатный повтор пакетов на CPU. Такой результат не принят как ускорение. В финальной v4 третьего массива нет: используются прежние два массива QueueItem и прежний лимит памяти. Пакеты не урезаются, отсечение не усиливается. Если штатная ёмкость всё же исчерпана, сохраняется полный CPU fallback без принятия неполной матрицы.

Бюджет очередей по-прежнему ограничен четвертью свободной VRAM с учётом собственной сохранённой памяти. Объём host RAM, число ориентаций и число отражений ради ускорения алгоритма не уменьшаются. Уменьшение локального стека ядра не означает такое же уменьшение всей используемой VRAM.

Для матриц используются |ΔMij|/M11 и разности нормированных отношений для всех 16 элементов. Для интегралов — масштаб Cext/Csca. Пороги: 10⁻⁵ для float и 10⁻⁷ для double. Сырые пучки сравниваются с CPU до дифракции: число, пути, грани, полигоны, площадь, направление, поляризация, оптический путь и матрица Джонса. Линейные величины нормируются на размер; порог 10⁻⁸.

При n=18 и cutoff off на выбранном столбике обе реализации достигли штатного лимита очереди и полностью перешли на CPU; полученные матрицы и интегралы совпали точно. Это существующее ограничение GPU-очереди, а не потеря пучков. При n=18 и balanced сравнение сырых пучков выполнено на GPU.

Проверка постоянного worker охватывает смену когерентности, размера, глубины, числа ориентаций, отсечения, попадания в кэш и возврат к прежнему запросу. Для поглощающей и невыпуклой частицы проверен штатный CPU-путь. В тестах скорости resident все ориентации обязаны пройти GPU; неожиданный CPU fallback останавливает тест.

Запуск экспериментального режима

env MBS_GPU_TRACE_CONVEX_SCHEDULE=split8 \
    MBS_GPU_TRACE_CONVEX_WORKSPACE_MIB=0 \
    "$MBS_BINARY" --allow-experimental-environment \
    --po-trace-backend resident --method po --backend cuda \
    --particle 4 35.395 --symmetry 2 6 \
    --wavelength-um .532 --ri 1.3116 0 \
    --sobol-seed 1024 131 --haar-alpha --threads 2 \
    --orientation-pipeline --orientation-chunk 32 \
    --max-reflections 12 --cutoff-profile off --phi-points 16 \
    --theta-grid-file theta.txt --trace-cache-mib 0 \
    --profile-phases --close --output droxtal_split_trial

Файл theta.txt содержит четыре угла из начала отчёта, каждый на своей строке. Путь MBS_BINARY приведён ниже. Для CPU+GPU используется --po-trace-backend hybrid. Значение split оставляет один поток на пучок на геометрическом этапе, split8 использует восемь. Значение legacy возвращает прежнее ядро. --allow-experimental-environment разрешает экспериментальные настройки и фиксирует их в логах. MBS_GPU_TRACE_CONVEX_WORKSPACE_MIB относится к прежнему необязательному кэшу выделений памяти; для основной итоговой проверки он выключен.

Новые режимы применяются к поддерживаемой GPU-трассировке PO. Они не выбираются автоматически в fullauto. Переключение текущих расчётов и миграция их чекпоинтов в этом эксперименте не выполнялись.
