# Что сохраняет fullauto

Новые рабочие запуски fullauto автоматически получают `--no-text-reports`.
Этот флаг отключает дублирующие текстовые файлы `*_log.txt` и `*_out.txt`.
Обычный запуск программы без fullauto по умолчанию продолжает создавать их.
Для него этот же флаг можно задать вручную.

Изменение распространяется на PO и GO, на отдельные рабочие процессы и на
постоянно работающий процесс, обслуживающий несколько заданий. У PO также
учтены результаты для меньшей глубины отражений, сохранённые префиксы
ориентаций и матрицы без тени. Запись интегральных характеристик не создаёт
дублирующий лог заново.

## Какие данные остаются

| Данные | Где находятся |
|---|---|
| Основной журнал рабочего запуска, ошибки, диагностика трассировки и интегралы | `jobs/<id>/stdout.log` |
| Точная команда запуска, включая `--no-text-reports` | `jobs/<id>/command.args` |
| Матрицы, в том числе меньшая глубина и префиксы ориентаций | `jobs/<id>/result/*.dat` |
| Интегральные характеристики | `jobs/<id>/result/*_integrals.tsv` |
| Времена фаз, аналитические коэффициенты и необходимые поправки интегралов | соответствующие TSV/TXT в `result` |
| Подтверждение целостности блока, связи между исходными задачами | `complete.txt`, манифесты и индекс |
| Выбранные N, φ, глубины отражений, промежуточные матрицы и ошибки | файлы контроллера и `round_snapshots` |
| Политика записи новых рабочих результатов | `worker_output_policy.json` |

Отключается только дополнительная текстовая копия отчётов. Расчёт матриц,
суммирование, интегралы и критерии точности этот флаг не меняет. Основной
журнал сохраняет вывод stdout и stderr рабочего процесса.

## Восстановление

Флаг добавляется в команду непосредственно перед запуском рабочего процесса,
после определения идентификатора его вычислительного блока. Он не делает
старый численный блок недействительным только из-за изменения записи отчёта.
Полная команда с флагом сохраняется в `command.args`.

Для продолжения прерванного расчёта используйте прежнюю команду с тем же
каталогом результата и совместимым бинарником. Не меняйте параметры
произвольно: fullauto проверяет идентичность конфигурации и целостность
завершённых блоков. Совместимость оптического ядра при смене версии проверяется
отдельно; `--no-text-reports` не отменяет эту проверку.

Существующие файлы этим изменением не удаляются. Оно предотвращает накопление
новых дубликатов. Матрицы и граф зависимостей для восстановления продолжают
занимать место; эта правка не вводит удаление численных чекпоинтов или жёсткий
предел размера каталога.

## Проверка

```bash
make -C cpu -j4
python3 tests/test_fullauto_worker_storage.py \
  --binary cpu/bin/mbs_po_mpi --output /tmp/mbs-storage-check
python3 tests/test_fullauto_outputs.py \
  --binary cpu/bin/mbs_po_mpi --output /tmp/mbs-output-check
```

Первый тест сравнивает численные файлы побайтно при включённых и отключённых
текстовых отчётах, затем прерывает настоящий расчёт и восстанавливает его.
Второй проверяет конечные и промежуточные результаты PO/GO, повторное открытие
завершённого расчёта и обнаружение повреждённых выходных файлов.
